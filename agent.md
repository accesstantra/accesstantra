# Accessible Tantra — Website Guide for Developers & AI Agents

This is the **authoritative guide** for working on the Accessible Tantra website. Read it
fully before making changes. It is written so that a new developer **or an AI coding agent**
can make correct changes without guessing. When in doubt, follow this document over your own
assumptions, and prefer small, data-driven edits over new code.

> **What this site is:** the website of **Accessible Tantra**, a non‑profit working to make
> every system and space accessible for persons with disabilities. Because accessibility *is
> the mission*, accessibility is a hard requirement on every change — not a nice-to-have.

---

## 0. GOLDEN RULES (do not break these)

1. **Accessibility is non‑negotiable.** Keep semantic HTML, labels, focus management, and
   contrast. See the [Accessibility checklist](#10-accessibility-checklist). If a change would
   reduce accessibility, don't make it.
2. **No inline styles.** All styling lives in CSS files using design tokens (CSS variables).
   Do **not** add `style={{...}}` to components. See [Styling](#9-styling-system).
3. **Exactly one `<h1>` per page.** On the **Home** page the `<h1>` is the site title in the
   header (`Header.jsx`); every other page provides its own `<h1>` (usually inside
   `.page-hero`). Don't add a second `<h1>`.
4. **Never use `href="#something"` for in‑page links.** Routing uses **HashRouter**, so any
   `#...` href changes the route and breaks the page. To move focus/scroll within a page, use
   a `<button>` with an `onClick` that calls `element.focus()` (see the skip link in
   `Header.jsx` and "Skip to form" in `ContentPage.jsx`).
5. **Keep `vite.config.js` `base: '/'` and `public/CNAME` (`accesstantra.com`).** These make
   the custom domain work. Changing them breaks the live site's CSS/JS or the domain.
6. **Prefer embedded Google Forms** (`type: 'embed'`) over native ones — see
   [Forms](#83-add-or-change-a-form-google-forms). Native forms fail silently if the Google
   Form collects a *verified* email.
7. **Hindi text must have `lang="hi"`** on its element so screen readers pronounce it
   correctly.
8. **Don't remove `{ preventScroll: true }`** in `Layout.jsx` — without it the Home page header
   scrolls off-screen and renders blank.
9. **Most content changes are data edits**, not component edits. Edit files in `src/data/`.
   Adding/removing an initiative, course, or past event automatically updates the nav, routes,
   and listing pages.
10. **Don't edit `dist/`.** It is generated by `npm run build`. Edit `src/`.


with no errors, and the page looks/behaves correctly. Always run `npm run build` before you

## 4. How the app works (data flow)

```
index.html (#root, theme script)
   └─ main.jsx  → <HashRouter><App/></HashRouter>
        └─ App.jsx  → <Routes> under <Layout/>
             └─ Layout.jsx → <Header/> + <main id="main-content"><Outlet/></main> + <Footer/>
                  └─ the matched page component renders inside <main>
```

- **Routing is hash-based** (URLs look like `https://accesstantra.com/#/about`). This is on
  purpose so GitHub Pages serves deep links without a server. Do not switch to BrowserRouter.
- **`Layout.jsx`** renders the global chrome and, on every route change, scrolls to top and
  moves keyboard focus into `<main>` (with `preventScroll: true`).
- **Data‑driven pages:** `App.jsx` maps a URL param to a data object and passes it to the
  generic **`ContentPage`**. So you usually add content by editing a data file — no new
  component or route needed.
- **The nav builds itself from data:** `Header.jsx` builds the **Programs** dropdown from
  `initiatives.js`. Add an initiative → it appears in the dropdown, on `/initiatives`, on the
  Home grid, and at `/programs/<id>` automatically.

## 5. Routing map (`src/App.jsx`)

| Path | Renders | Source of content |
|---|---|---|
| `/` | `Home` | `pages/Home.jsx` (hand-written sections) |
| `/about` | `About` | `pages/About.jsx` |
| `/initiatives` | `InitiativesOverview` | maps over `data/initiatives.js` |
| `/programs/:programId` | `ContentPage` | `getInitiative(programId)` from `initiatives.js` |
| `/courses` | `CoursesLanding` | `data/courses.js` (`courses` + `coursesLanding`) |
| `/courses/:courseId` | `ContentPage` | `getCourse(courseId)` from `courses.js` |
| `/past-events` | `PastEvents` | `data/pastEvents.js` |
| `/contact` | `Contact` | `pages/Contact.jsx` |
| `/what-we-do` | redirect → `/initiatives` | legacy redirect (keep) |
| anything else (`*`) | `ContentPage` with no data | shows a graceful "Not available" page |

If `getInitiative`/`getCourse` returns `undefined` (unknown id), `ContentPage` shows the
"Not available" page — so removing an item never crashes the site.

## 6. The `ContentPage` page object (most important data shape)

`ContentPage` (`src/components/ContentPage.jsx`) renders any object with this shape. Both
`initiatives.js` items and `courses.js` items use it.

```js
{
  // --- hero ---
  title: 'Mentorship Programme',          // becomes the page <h1> (required)
  subtitle: 'Short line under the title', // optional, shown as .lead
  meta: { Starts: '21 June', Cost: 'Free' }, // optional key→value chips ("Starts: 21 June · Cost: Free")

  // --- body (these are the fields the Hindi toggle swaps) ---
  intro: 'One paragraph' ,                // string OR array of strings (each becomes a <p>)
  sections: [                             // optional list of content blocks
    { heading: 'What you will learn', list: ['item 1', 'item 2'] },
    { heading: 'Please note', body: 'A paragraph or array of paragraphs' },
  ],

  // --- optional form section ---
  formHeading: 'Registration form',       // if present (or `form` present) a form section renders
  formIntro: 'Fill the form below.',      // paragraph(s) above the form
  form: {                                 // optional embedded or native form
    type: 'embed',
    src: 'https://docs.google.com/forms/d/e/XXXX/viewform?embedded=true',
  },

  // --- optional extras ---
  ctas: [                                 // buttons; internal use `to`, external use `href`
    { label: 'Contact us', to: '/contact', variant: 'primary' },
    { label: 'YouTube', href: 'https://...', variant: 'outline' },
  ],
  returnHome: true,                       // adds a "Return to home" button at the bottom

  // --- optional Hindi translation ---
  hi: {                                   // if present, an English/हिन्दी toggle appears and
    intro: [...],                         //   swaps intro + sections + formIntro to Hindi.
    sections: [...],                      //   Mirror the English structure.
    formIntro: '...',
  },
}
```

Notes:
- `intro` and `section.body` accept **a string or an array of strings** (array → multiple `<p>`).
- A **"Skip to form"** button appears automatically when `form` is present.
- `meta` renders as a single line of `Key: value` chips.
- The Hindi toggle only appears when `hi` exists. The page title/meta/CTAs stay English by design.

## 7. Data files reference (`src/data/`)

### `site.js` — shared constants (import these, don't hardcode)
```js
export const YOUTUBE_URL = 'https://www.youtube.com/@accessibletantra'
export const WHATSAPP_SUPPORT_NUMBER = '917260920093'   // E.164 w/o '+', for wa.me links
export const CONTACT = { email: 'accesstantra@gmail.com',
                         phoneDisplay: '+91 72609 20093', phoneTel: '+917260920093' }
```

### `initiatives.js` — the "Programs" dropdown + their pages
- `export default initiatives` — array of `ContentPage` objects, **plus** `navLabel` (dropdown
  text) and `tagline` (used on cards). Current ids: `digital-literacy`, `mentorship`,
  `collaboration`, `digital-training-request`.
- `export const initiativesIntro` — intro paragraph for the `/initiatives` page.
- `export function getInitiative(id)` — used by the `/programs/:id` route.
- Adding/removing an object here updates: Programs dropdown, `/initiatives`, Home grid, and the
  `/programs/<id>` page. **No other file needs editing.**

### `courses.js` — courses + the `/courses` landing
- `export default courses` — array of `ContentPage` objects with extra fields `navLabel`,
  `tagline`, `upcoming` (boolean: list it on `/courses`), `meta`. **Currently empty `[]`**, so
  `/courses` shows the "no upcoming courses" message + standing links.
- `export const coursesLanding = { title, intro, noCoursesMessage, standingLinks: [...] }` —
  the always-visible links on `/courses` (e.g. "Request customized digital training", YouTube).
- `export function getCourse(id)`.

### `pastEvents.js` — past events
```js
const pastEvents = [
  { id, title, date, summary, winners: ['...'], youtubeId: 'm_0UUjlJpkU' },
]
export default pastEvents
```
- Rendered by `pages/PastEvents.jsx`: shows **4 at a time** with a **"View more"** button.
- **Order = array order** (top of array → top of page). There is **no automatic date sorting**.
  To show a new event first, put it at the **start** of the array; to stack it below the latest,
  add it at the **end**.
- `youtubeId` is just the id from a YouTube URL (`watch?v=<id>`); it's embedded responsively via
  the `.video-embed` (16:9) wrapper. `winners` is optional.

## 8. Step-by-step recipes

### 8.1 Edit the Home announcement
The announcement is a hand-written `<section aria-labelledby="home-announcements">` near the top
of `src/pages/Home.jsx`. Edit the heading/paragraph/button there. For one-off events, keep it
short and link to the relevant page. When an event is over, move it to **Past Events**
(`pastEvents.js`) and restore an evergreen announcement.

### 8.2 Add / edit / remove an initiative (a "Program")
Edit **`src/data/initiatives.js`** only.
- **Add:** append an object using the [ContentPage shape](#6-the-contentpage-page-object-most-important-data-shape) plus `navLabel` and `tagline`. Choose a unique kebab-case `id`.
  It instantly appears in the Programs dropdown, the Home "Our initiatives" grid, the
  `/initiatives` overview, and at `/programs/<id>`.
- **Edit:** change the object's fields.
- **Remove:** delete the object. Its nav item, card, and page disappear; old links fall back to
  the "Not available" page.

Example minimal initiative:
```js
{
  id: 'awareness',
  navLabel: 'Awareness',
  title: 'Awareness Programme',
  tagline: 'Spreading accessibility awareness.',
  intro: 'We run awareness drives across schools and workplaces.',
  ctas: [{ label: 'Contact us', to: '/contact', variant: 'primary' }],
}
```

### 8.3 Add or change a form (Google Forms)
Two ways. **Prefer `embed`.**

**A) Embed (recommended, robust):** put the form's *embedded* URL on the page object:
```js
form: { type: 'embed',
        src: 'https://docs.google.com/forms/d/e/<FORM_ID>/viewform?embedded=true' }
```
Get the URL from the Google Form's **Send → `<>` Embed HTML** (or just append
`?embedded=true` to the `viewform` URL). The form renders in an iframe on the page; works
regardless of the form's email settings.

**B) Native (only if you specifically want our own styled fields):** uses
`RegistrationForm.jsx` and requires the form's field ids:
```js
form: {
  type: 'native',
  action: 'https://docs.google.com/forms/d/e/<FORM_ID>/formResponse',
  fields: [ { entry: 'entry.123', label: 'Name', type: 'text', required: true }, ... ],
}
```
⚠️ **Gotcha:** if the Google Form has **"Collect email addresses = Verified"**, native
submissions are silently rejected (no row recorded). Fix in the Google Form: set "Collect email
addresses" to **Do not collect** (or use the embed approach). To find `entry.*` ids, open the
live form, View Source, and read the `FB_PUBLIC_LOAD_DATA_` array (each question's entry id).

### 8.4 Add a past event
Add an object to the array in **`src/data/pastEvents.js`** (see
[pastEvents reference](#pasteventsjs--past-events) for ordering). Provide `title`, `date`,
`summary`, optional `winners`, and `youtubeId`. Nothing else to wire up.

### 8.5 Add a brand-new page + nav item
1. Create `src/pages/MyPage.jsx` (use `.page-hero` for the hero with the page's single `<h1>`,
   then `.section`/`.container` for content; reuse utility classes).
2. Add a route in `src/App.jsx`: `<Route path="my-page" element={<MyPage />} />`.
3. Add a nav link in `src/components/Header.jsx` (a `<li><NavLink to="/my-page" …>` in the
   `<ul className="site-header__list">`) and, optionally, in `src/components/Footer.jsx`
   `quickLinks`.
If the page is just title + text + optional form, you don't need a new component — add the data
to an existing data file and reuse `ContentPage` via a route instead.

### 8.6 Add a Hindi translation to a page
Add a `hi: { intro, sections, formIntro }` object to that page's data, mirroring the English
fields. The English/हिन्दी toggle then appears automatically (handled by `ContentPage` +
`LanguageToggle`). Put `lang="hi"` on any Hindi you add directly in JSX (e.g. in `Home.jsx`).

### 8.7 Change links, phone, email, social
- YouTube / WhatsApp support number / email+phone → `src/data/site.js`.
- Footer social + WhatsApp channel links → `src/components/Footer.jsx` (`social` array).
- Contact page phone + form target email → `src/pages/Contact.jsx` (uses `CONTACT` from
  `site.js`).
- The computer-support WhatsApp deep link uses `WHATSAPP_SUPPORT_NUMBER` from `site.js`.

## 9. Styling system

- **No CSS framework.** Styling = **design tokens (CSS variables)** + **utility classes** in
  `src/index.css`, plus a few per-component `.css` files. **Never use inline `style={{}}`.**
- **Tokens** are defined in `:root` and overridden in `[data-theme='dark']` (both in
  `index.css`). Examples: `--color-primary`, `--color-text`, `--color-bg`, `--color-bg-alt`,
  `--color-surface` (card backgrounds), `--color-accent` (teal accents), `--color-border`,
  `--color-on-primary` (text on filled buttons), `--color-error`, `--shadow-sm/md/lg`,
  `--radius`, `--radius-lg`. **Always use these variables** so light + dark both work; never
  hardcode a hex color in a component CSS file — add/extend a token instead.
- **Key utility classes** (already styled, just use them):
  `.container` (max-width + padding), `.section` / `.section--alt` (vertical bands, alt = tinted),
  `.page-hero` (gradient hero with the page `<h1>`), `.lead` (intro text),
  `.grid` + `.grid-2` / `.grid-3` (responsive grids), `.card` + `.card-list` (cards, hover-lift),
  `.btn` + `.btn-primary` / `.btn-outline` + `.btn-row` (buttons), `.program-embed` (Google form
  iframe), `.video-embed` (responsive 16:9 video), `.sr-only` (screen-reader-only),
  `.skip-nav` (skip link), `.content-meta`, `.content-block`, `.lang-bar`.
- **Dark mode:** `ThemeToggle.jsx` sets `data-theme="dark"|"light"` on `<html>` and saves it to
  `localStorage`. `index.html` has a tiny inline script that applies the saved theme before paint
  (prevents a flash). Default is light. Because everything uses tokens, dark mode "just works" —
  keep it that way.
- **Motion:** hover lifts/transitions are gated by a `@media (prefers-reduced-motion: reduce)`
  block in `index.css`. Keep new animations subtle and inside that guard.
- Section `h2` headings automatically get a small teal accent underline (via `.section h2::after`)
  and prose `<ul>` lists (that aren't `role="list"`) get teal markers — this is global, so you
  usually get the right look for free.

## 10. Accessibility checklist (run through this on EVERY change)

- [ ] **One `<h1>` per page** (header title on Home; page hero elsewhere). Headings nest
      logically (h1 → h2 → h3, no skipping).
- [ ] **Landmarks intact:** `<header>`, `<nav aria-label="…">`, `<main id="main-content">`,
      `<footer>` (provided by `Layout`/`Header`/`Footer` — don't duplicate).
- [ ] **Every form control has a `<label htmlFor>`** (or a clear `aria-label`). Errors use
      `role="alert"`; invalid fields get `aria-invalid`.
- [ ] **Keyboard only works:** tab order is logical, focus is always visible (the global
      `:focus-visible` outline — never remove it), dropdowns close on Escape.
- [ ] **No `href="#..."`** (HashRouter trap). Use a button + `focus()` to move within a page.
- [ ] **External links:** `target="_blank" rel="noopener noreferrer"` **and** a visually-hidden
      "(opens in a new tab)" note (`<span className="sr-only">`).
- [ ] **iframes have a descriptive `title`** (Google forms, YouTube videos).
- [ ] **Hindi text has `lang="hi"`.**
- [ ] **Contrast meets WCAG AA** in light *and* dark (that's why you use tokens).
- [ ] Decorative images use `alt=""`; meaningful images have real `alt`.

## 11. Deploy & verify

- **Deploy = push to `main`.** `.github/workflows/deploy.yml` builds the site (Node 20,
  `npm ci`, `npm run build`) and publishes `dist/` to GitHub Pages. Takes ~1–2 minutes.
- **Verify it shipped:** load `https://accesstantra.com/` and check the hashed bundle name in the
  HTML (`/assets/index-XXXX.js`) matches the one `npm run build` printed locally. Hard-refresh
  (Ctrl/Cmd+Shift+R) since the browser caches aggressively.
- **A 404 right after a domain/Pages change is usually NOT a bug** — GitHub's CDN (Fastly) can
  serve a stale "Site not found" for up to ~10 minutes. It clears itself; a re-deploy/push
  helps. The site only truly breaks if `base` ≠ `/` or `public/CNAME` is missing.
- GitHub Pages **Settings → Pages** must stay: Source = **GitHub Actions**, custom domain =
  `accesstantra.com`, Enforce HTTPS on.

## 12. Gotchas & troubleshooting

| Symptom | Cause / Fix |
|---|---|
| Clicking an in-page link blanks the page | An `href="#..."` changed the hash route. Use a `<button onClick>` that focuses the target instead. |
| Native form "submits" but no responses appear | Google Form "Collect email = Verified" silently drops anonymous posts. Set it to *Do not collect*, or switch to `type:'embed'`. |
| Site CSS/JS 404s after deploy | `vite.config.js` `base` is not `/`, or `public/CNAME` was removed. Restore them. |
| Home header is blank | The `focus(...)` in `Layout.jsx` lost `{ preventScroll: true }`. Restore it. |
| Live site shows old content | Browser/CDN cache. Hard-refresh; wait a few minutes; confirm the bundle hash. |
| `LF will be replaced by CRLF` warnings on commit | Harmless on Windows. Ignore. |
| Edited `dist/` and nothing changed | `dist/` is generated. Edit `src/` and rebuild. |
| New initiative/course not showing | It must be a correctly-shaped object in the right data file with a unique `id`; run `npm run build` to surface syntax errors. |

## 13. Glossary

- **Initiative / Program** — same thing here: an entry in `initiatives.js`, shown under the
  **Programs** dropdown, at `/programs/<id>`. (The code says "program" in routes/components and
  "initiative" in the data — they refer to the same items.)
- **Course** — an entry in `courses.js`, shown under **Courses** (`/courses/<id>`). Currently
  there are none (empty array).
- **Past Event** — a finished event in `pastEvents.js`, shown on **/past-events** with a YouTube
  recording.
- **Embed form vs native form** — *embed* shows the Google Form in an iframe (robust, preferred);
  *native* renders our own fields that POST to the Google Form (needs entry ids; breaks on
  verified-email forms).
- **ContentPage** — the one generic component that renders initiative/course/fallback pages from
  a data object.
